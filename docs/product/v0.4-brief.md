# v0.4 Product Brief: Project Monitor + Usage Diagnostics

状态: Ready for Dev Agent

负责人: 产品经理

日期: 2026-06-26

## 1. 背景

v0.2 已完成决策层，v0.3 已完成 Project Focus 和项目分布修复。当前看板已经能回答“哪个项目在烧”，下一步要回答:

1. 哪些项目正在异常升温，需要我停一下或换策略?
2. 某个项目最近几天的消耗趋势、cache 结构和模型结构是否健康?
3. 我能不能把一段用量手动标成某个任务，做事后复盘?
4. Agent 工作流是不是越来越“放大”，即一条用户指令触发越来越多模型调用?
5. Atmo 的本地 quota API 是否能随菜单栏 App 自动保持可用?

用户明确本轮不做人民币估算。

## 2. 一句话目标

打开完整窗口后，用户能在 10 秒内识别高消耗项目、异常升温项目、任务级粗略成本和 Agent 放大趋势；同时 Atmo Agent 可以稳定查询本机 quota API。

## 3. 必做范围

### P0.1 Project Monitor 项目监控

目标: 在“全部项目”状态下，给出项目级风险雷达，不需要用户逐个点项目。

必须展示:

- 今日 Top 项目。
- 今日项目占比。
- 近 7 天趋势: 上升 / 平稳 / 下降 / 数据不足。
- 相比近 7 天日均的涨幅。
- Fresh Tokens。
- Cache Read Share。
- 等价 USD。
- 最后活跃日期。
- 状态标签:
  - `活跃`: 今日有明显用量。
  - `升温`: 今日用量高于近 7 天日均。
  - `高缓存`: cache read share 高，提示总 token 可能虚高。
  - `数据不足`: 历史天数不足，不能判断趋势。

交互:

- 点击项目进入现有 Project Focus。
- 支持按 Token / USD 当前 metric 切换排序展示。
- 受工具筛选、周期筛选、模型显隐影响。

验收:

- 在 `Codex` + `全部` 下能看到非空 Project Monitor。
- 至少展示 Top 5 项目。
- 选中某个项目后，Project Monitor 与 Project Focus 口径一致。
- 无项目数据时显示“暂无项目监控数据”，不能出现 `NaN` / `undefined`。

### P0.2 Project View Enhancement 项目视图增强

目标: 选中项目后，Project Focus 不只显示静态汇总，还能解释项目健康度。

必须增强:

- 近 7 天项目用量 mini trend 或紧凑日序列。
- 今日 vs 近 7 天日均。
- Fresh / Cache Read 结构。
- Top Models 更明确显示 fresh tokens、cache read share、等价 USD。
- 项目状态摘要:
  - `今天明显升温`
  - `缓存读取占比较高`
  - `主要消耗来自 {model}`
  - `近 7 天数据不足`

验收:

- 选中项目后能看到 7 天趋势和状态摘要。
- 切换 Token / USD、工具、周期、模型显隐后，Project Focus 增强内容同步变化。
- 默认仍不展示 raw `/Users/...` 或 `~/...` 项目路径。

### P1.1 Session / Task 数据基础

目标: 为任务标签和 Agent 放大趋势提供低风险数据基础。

允许新增派生字段:

- `sessions[]`: 按本地日志文件或 session id 聚合的只读派生数据。
- `daily[].agentStats`: 按天聚合模型调用数、用户回合数和放大倍数。
- `projects[].lastActiveDate` 或等价前端可计算字段。

`sessions[]` 建议字段:

```json
{
  "id": "脱敏后的 session id 或文件 hash",
  "tool": "codex",
  "projectId": "~/ai额度app",
  "projectName": "ai额度app",
  "startedAt": "2026-06-26T10:00:00.000Z",
  "endedAt": "2026-06-26T10:30:00.000Z",
  "modelCallCount": 12,
  "userTurnCount": 4,
  "amplification": 3,
  "tok": 123456,
  "usd": 1.23,
  "tokBreakdown": { "input": 1, "output": 1, "cacheWrite": 0, "cacheRead": 1 },
  "usdBreakdown": { "input": 0.1, "output": 0.2, "cacheWrite": 0, "cacheRead": 0.01 }
}
```

约束:

- session id 如来自文件名或日志路径，必须脱敏或 hash，不暴露完整本机路径。
- 不读取、不展示 `message.content`。
- 如果某工具无法可靠得到 `userTurnCount`，填 `null`，UI 显示“数据不足”，不得编造放大倍数。
- 不改变现有 day / model / project 计费口径，只新增派生输出。

### P1.2 任务级成本手动标签

解释: 这不是自动识别“你在做哪个功能”。第一版是用户手动给一组 session、项目 + 日期范围打标签，例如:

- `v0.4 项目监控`
- `面试 Skill 调试`
- `AI 视觉工作流 Review`

系统只把已存在用量按用户选定范围汇总，帮助复盘“这个任务大概花了多少 token / USD”。

必须支持:

- 新建 / 编辑 / 删除本地任务标签。
- 标签字段:
  - 名称。
  - 颜色或短标识。
  - 项目。
  - 日期范围。
  - 可选 session 列表。
- 展示每个标签的 token、等价 USD、Fresh Tokens、Cache Read Share。
- 标签数据存本机 `localStorage` 即可，不要求写服务器文件。

验收:

- 用户能在 UI 中创建一个任务标签。
- 刷新页面后标签仍在。
- 标签汇总随当前 usage 数据变化重新计算。
- 不新增服务端写接口。
- 不读取对话正文，不做自动语义分类。

### P1.3 Agent 放大倍数趋势

目标: 观察“一个用户回合触发多少模型调用”的趋势，帮助判断 Agent 工作流是否越来越重。

计算:

- `modelCallCount`: 有 token 用量的模型调用数。
- `userTurnCount`: 能从元数据可靠识别的用户回合数。
- `amplification = modelCallCount / userTurnCount`。

展示:

- 近 7 / 30 天趋势。
- 今日放大倍数。
- 按工具区分 Claude Code / Codex。
- 如果 `userTurnCount` 缺失，展示模型调用数趋势，并标注“用户回合数不足，暂不计算倍数”。

验收:

- 至少能展示模型调用数趋势。
- 能计算的工具显示 amplification。
- 不能计算的工具不显示假数值。
- 不读取或展示用户消息正文。

### P0.5 Quota API 常驻

目标: 菜单栏 App 启动后，本地 quota API 默认可用，Atmo Agent 不需要手动执行 `node engine/quota-api.mjs`。

推荐实现:

- 复用现有 macOS App 启动 `engine/usage-data.mjs --serve` 的模式。
- 菜单栏 App 启动时确保 `engine/quota-api.mjs` 在 `127.0.0.1:8765` 运行。
- App 退出时只停止自己拉起的 quota API 子进程，不误杀用户自己启动的其他进程。
- 如果端口已被占用:
  - `/health` 返回 `service=quota-app` 时复用。
  - 否则记录错误，不强行抢端口。
- README 补充常驻行为和手动启动兜底。

验收:

- 打包 App 启动后，`curl http://127.0.0.1:8765/health` 返回合法 JSON。
- `curl http://127.0.0.1:8765/quota` 返回合法 JSON。
- 退出 App 后，若 quota API 是 App 拉起的，应停止；若是外部已有服务，不应被停止。
- 不监听公网地址。
- 不提供写操作。

## 4. 非目标

本轮不做:

- 人民币估算 / RMB 汇率。
- 自动任务分类。
- 读取、展示、解析对话正文。
- 语义分析对话内容。
- 企业级 BI 报表。
- 模型降级假设计算器。
- 完整月报 / 周报。
- 修改已 vet 的计费价格、UTC+8、去重、cache 计费核心口径。

## 5. 数据与隐私口径

- 允许读取字段: timestamp、cwd、session id、request id、message id、usage、model、rate limit、error/status 元数据。
- 禁止读取或展示字段: `message.content`、prompt 正文、response 正文、secret、token、cookie、authorization。
- 项目路径默认仍只展示 `project.name`。
- 所有按天统计沿用 UTC+8。
- 新增 session / task 字段必须是派生数据，不得改变现有 `daily[]` 和 `projects[]` 的总账。

## 6. 推荐实现顺序

1. 数据基础: 新增 session 和 agentStats 派生输出，确保现有总账不变。
2. Project Monitor 和 Project Focus 增强。
3. 任务标签本地 UI。
4. Agent 放大趋势 UI。
5. Quota API 常驻接入菜单栏 App。
6. README 和开发笔记收口。

如果开发中发现 session/userTurn 数据不可可靠提取，优先保证 Project Monitor、Project View Enhancement 和 Quota API 常驻完成；任务标签和 Agent 倍数可降级为“数据不足”状态，不允许伪造。

开发完成后必须按交付隔断规则:

- 写开发笔记。
- 登记 `.agent-team/交付收件箱.md`。
- 更新 `.agent-team/文件变更记录.md` 和溯源。
- 只发短通知给产品经理，包含交付ID、任务ID、结果位置、是否需要 Review。

质量评审必须复核:

- 数据总账没有因为 session 派生而漂移。
- 默认 UI 不泄露路径或正文。
- 任务标签不提供服务端写接口。
- Agent 倍数缺数据时没有假数值。
- quota API 只监听本机且 App 只停止自己拉起的进程。

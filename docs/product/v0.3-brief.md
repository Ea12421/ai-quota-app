# v0.3 Product Brief: Project Focus Drill-down

状态: Ready for Dev Agent

负责人: 产品经理

日期: 2026-06-26

## 1. 背景

v0.2 Decision Layer 已完成 Burn-down Forecast、Real Cost View 和 Today's Top Projects。验收时留下一个明确的 v0.3 跟进点:

- 默认展示 `~/...` home-relative project path 虽不泄露 raw HOME 绝对路径，但截图或分享时仍可能暴露个人项目结构。

长期路线图中的 v0.3 是 Drill-down Layer，最终目标是从项目定位到具体 window / session。当前 `usage.json` 仍只有 `projects[]` 和 `daily[].byProject`，还没有正式 session/window 输出。因此 v0.3 第一轮不直接做 session 数据模型，而是先做低风险的项目焦点下钻:

- 默认隐藏项目路径。
- 选中项目后提供更清晰的项目焦点面板。
- 用现有 `daily.byProject` 和 `projects` 数据回答“这个项目今天、当前区间、模型结构、cache 结构如何”。

## 2. v0.3 小版本目标

一句话目标: 用户可以安全地截图分享看板，同时能从 Top 项目点击进入项目焦点视图，快速判断该项目的今日消耗、区间消耗、fresh/cache 结构和主要模型。

必须回答:

1. 当前页面默认是否不暴露项目路径?
2. 我选中的项目今天烧了多少?
3. 我选中的项目在当前区间的等价 USD、fresh tokens、cache read share 是多少?
4. 该项目主要由哪些模型和工具贡献?

## 3. 必做范围

### P0.1 Share-safe Project Display

需求:

- 默认页面可见区域只展示 `project.name`。
- 不在项目筛选栏、项目榜卡片、Decision Strip 默认可见文案中展示 `project.path`。
- 如需要保留路径信息，只能放在显式详情态、调试态、或用户主动展开后展示。
- 即使展示路径，也只能使用 engine 已处理后的 `project.path`，不得重新引入 raw `/Users/...` 绝对路径。

验收:

- 打开完整窗口默认状态，不应看到 `~/` 开头路径或 `/Users/` 绝对路径。
- 选择具体项目后，默认仍以项目名为主。
- `unknown` 项目显示为“未知项目”，不能隐藏。

### P0.2 Project Focus Panel

需求:

- 当 `projectSelect` 选择具体项目时，在完整窗口首屏或项目分布区上方展示项目焦点面板。
- 面板至少包含:
  - 项目名。
  - 当前筛选区间等价 USD。
  - 当前筛选区间 Fresh Tokens。
  - 当前筛选区间 Cache Read Share。
  - 今日 UTC+8 等价 USD / Fresh Tokens。
  - 工具标签。
  - 一键清除项目筛选。
- 当前筛选区间必须受周期、工具、模型显隐影响。
- 今日指标必须使用 `daily[daily.length - 1].date` 的 `byProject`，沿用 UTC+8 口径。

验收:

- 点击 Today's Top Projects 或项目分布卡片后，项目焦点面板出现。
- 点击“清除项目筛选”后回到全部项目。
- 缺少项目数据时降级显示，不出现 `NaN`、`undefined`。

### P0.3 Project Model Mix

需求:

- 在项目焦点面板中展示该项目当前区间 Top 模型，至少 Top 3。
- 每个模型展示:
  - 模型名。
  - 等价 USD 或 token，跟随当前 `Token / USD` 切换。
  - Fresh Tokens。
  - Cache Read Share。
- 模型显隐开关必须影响项目焦点面板的汇总和 Top 模型。

验收:

- 选中项目后能看到该项目主要模型。
- 切换 Token / USD 或隐藏某模型后，面板数值同步刷新。

## 4. 非目标

本轮不做:

- 不读取、不展示对话正文。
- 不新增 session/window 数据模型。
- 不做当前窗口上下文占用监控。
- 不做错误 / retry 浪费统计。
- 不做小时级 velocity。
- 不新增依赖。
- 不重写 engine 核心计费、去重、UTC+8、cache 或 `<synthetic>` 过滤口径。
- 不要求修改 `engine/`，除非 Dev 能证明是极小、必要、且不改变核心口径的派生字段。

## 5. 数据口径

必须复用:

- `projects[]`
- `daily[]`
- `daily[].byProject`
- `daily[].byProject[projectId].byModel`
- `tokBreakdown`
- `usdBreakdown`
- 当前前端已有的周期、工具、项目、模型显隐筛选状态

计算口径:

- Fresh Tokens = `input + output + cacheWrite`
- Cache Read Share = `cacheRead / (fresh + cacheRead)`
- Equivalent USD = `input + output + cacheWrite + cacheRead` 的 USD breakdown 汇总
- 今日数据 = `daily[daily.length - 1]`
- 当前区间数据 = 当前前端筛选后的可见 days 汇总

## 6. 页面建议

推荐最小 UI:

- 移除或默认隐藏顶部项目栏中的 `projectPath` 可见文本。
- 在项目分布区域上方新增 `Project Focus` 面板，仅在选中项目时显示。
- 面板用紧凑指标和小表格，不做重图表。
- 现有 Today's Top Projects、项目分布卡片继续可点击筛选项目。

不要做:

- 不要新增复杂导航。
- 不要把页面做成多层路由。
- 不要把路径作为视觉主信息。

## 7. 验收标准

### 功能验收

- [ ] 默认完整窗口不展示 home-relative path 或 raw HOME path。
- [ ] 选中项目后出现 Project Focus 面板。
- [ ] Project Focus 展示当前区间 equivalent USD、Fresh Tokens、Cache Read Share。
- [ ] Project Focus 展示今日 UTC+8 项目用量。
- [ ] Project Focus 展示 Top 模型，并受模型显隐和 Token / USD 切换影响。
- [ ] 可一键清除项目筛选。
- [ ] Today's Top Projects 和项目分布卡片仍可点击进入筛选。

### 隐私验收

- [ ] 不读取、不解析、不展示 `message.content`。
- [ ] 默认 UI 不展示 raw `/Users/...`。
- [ ] 默认 UI 不展示 `~/...` 项目路径。
- [ ] 如有路径详情态，只能展示 engine 已脱敏后的 `project.path`。

### 工程验收

- [ ] 不新增依赖。
- [ ] 不要求修改 `engine/`；若修改，必须解释原因和未改变的核心口径。
- [ ] `node --check engine/lib.mjs engine/sources/claude.mjs engine/sources/codex.mjs engine/usage-data.mjs` 通过。
- [ ] `node engine/usage-data.mjs` 通过。
- [ ] `./app/build.sh` 通过。
- [ ] 浏览器验证 `?view=full` 和 `?view=popover` 无明显回归。

## 8. 交付要求

开发工程师完成时必须按 Atmo 协议交付:

- 实际变更文件。
- 是否超出授权 / 边界。
- 验证命令和结果。
- 是否改动 `engine/`。
- 是否读取或展示正文。
- 文件变更记录。
- 开发笔记。

质量评审必须检查:

- 功能是否满足本 brief。
- 隐私默认展示是否符合要求。
- 文件变更记录是否和 `git diff` 一致。
- 是否有未说明的越界变更。

## 9. 延后到后续 v0.3.x / v0.4

- 正式 session/window 数据模型。
- 当前窗口上下文占用估算。
- 最近 1h / 3h token velocity。
- 错误 / retry 浪费统计。
- 上下文卫生提醒。

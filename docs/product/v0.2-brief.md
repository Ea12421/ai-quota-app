# v0.2 Product Brief: Decision Layer

状态: Draft for Dev Agent

负责人: AI Dashboard - Product

日期: 2026-06-26

## 1. 背景

当前 v0.1 已经完成本机 macOS 菜单栏 App、完整窗口、Claude Code / Codex 本地用量聚合、5h / 7d 限额展示、项目维度聚合和项目筛选。现有看板已经能回答“用了多少”，但还不能稳定回答高频决策问题:

- 我现在还能不能继续跑?
- 哪些用量是真成本，哪些只是 cache read 把 token 数抬高?
- 今天到底哪个项目在烧?

v0.2 的目标是把看板从账单展示推进到使用决策助手，但不扩张到 session/window 下钻、上下文监控或语义分析。

## 2. v0.2 目标

一句话目标: 打开弹窗或完整窗口后，用户能在 10 秒内判断当前额度风险、真实成本结构和今天最主要的消耗项目。

v0.2 必须回答:

1. Burn-down Forecast: 按当前限额百分比燃烧速度，最紧的 5h / 7d 窗口会不会在 reset 前耗尽?
2. Real Cost View: 当前区间的等价 USD、fresh tokens、cache read 占比分别是多少?
3. Today's Top Projects: 今天 UTC+8 哪几个项目消耗最高，主要消耗来自哪个工具?

## 3. 非目标

v0.2 不做:

- 不读取、不展示 `message.content` 或任何对话正文。
- 不重写已 vet 的 `engine/` 核心计费、去重、UTC+8 按天、cache write 5m/1h 口径。
- 不展示剩余 token 绝对值，除非未来数据源提供明确 quota。v0.2 只有百分比预测。
- 不做 session/window 下钻。
- 不做当前窗口上下文占用监控。
- 不做任务自动分类、语义分析、企业 BI、复杂图表系统。
- 不自动判断 Opus / Sonnet 是否应该降级。
- 不做 live 汇率联网获取。RMB 估算延后，除非已有本地固定显示汇率且明确标注。

## 4. 目标用户和核心场景

目标用户是本机重度使用 Claude Code / Codex 的个人开发者或 AI product builder。典型使用方式是同时开多个项目和多个工具窗口，需要快速知道是否该继续跑、暂停、切工具或切项目。

核心场景:

- 开始大任务前: 看 5h / 7d 是否足够支撑接下来的工作。
- 跑任务过程中: 发现菜单栏限额变紧时，打开弹窗看预计是否会撞线。
- 当天复盘: 看今天哪个项目消耗最多，以及是真输出成本高还是 cache read 抬高 token。
- 异常上涨排查: 点击今日 Top 项目后，复用现有项目筛选查看趋势和模型拆分。

## 5. 当前可用数据契约

v0.2 应优先复用当前 `usage.json` 字段:

- `updatedAt`: 数据刷新时间。
- `limits[tool].fiveHour` / `limits[tool].sevenDay`: `{ pct, resetAt }`。
- `limits[tool].asOf`: 限额快照时间。
- `daily[]`: 已按 UTC+8 连续补齐的每日序列。
- `daily[].byModel[model]`: `{ tok, usd, tool, tokBreakdown, usdBreakdown }`。
- `daily[].byProject[projectId]`: `{ tok, usd, byModel }`。
- `projects[]`: `{ id, name, path, tok, usd, tools }`。
- `pricing`: 单价表。
- `notice`: 现有“等价价值，非真实账单”说明。

v0.2 不要求新增必需 engine 字段。Burn-down、Real Cost、Today's Top Projects 都可以由前端从现有 JSON 推导。

可选但不阻塞 v0.2 的增强字段:

- `decision.todayTopProjects`: 若 Dev 认为可降低前端复杂度，可在聚合层输出今日 Top 项目摘要。
- `recentWindows`: 最近 1h / 3h token 速度。当前 source adapters 输出到统一 `entries` 时已按天聚合，若要做小时级速度需要保留更细粒度 timestamp，不能作为 v0.2 必做。

## 6. 功能需求

### 6.1 Burn-down Forecast

目标: 让用户知道“按当前限额百分比燃烧速度，会不会在 reset 前耗尽”。

展示建议:

- 菜单栏弹窗: 在实时限额区域下方增加一行紧凑结论，例如“最紧: Codex 5h · 约 45m 后耗尽”或“按当前速度会先 reset”。
- 完整窗口: 在首屏 hero 或实时限额上方增加 Decision Strip，其中第一个单元展示 Burn-down。
- 完整窗口的实时限额卡继续列出各工具 5h / 7d，但补充 ETA 和风险状态。

预测口径:

- 对每个 `tool + window` 计算:
  - `pctUsed = limits[tool][window].pct`
  - `pctRemaining = max(0, 100 - pctUsed)`
  - `windowHours = 5` 或 `168`
  - `windowStart = resetAt - windowHours`
  - `elapsedHours = clamp(asOfOrUpdatedAt - windowStart, 0.05, windowHours)`
  - `pctPerHour = pctUsed / elapsedHours`
  - `etaHours = pctPerHour > 0 ? pctRemaining / pctPerHour : null`
  - `willExhaustBeforeReset = etaHours != null && now + etaHours < resetAt`
- `asOfOrUpdatedAt` 优先用 `limits[tool].asOf`，缺失时用 `updatedAt`。
- 如果 `resetAt` 缺失或 `pct` 缺失，显示“限额数据不足”，不做 ETA。
- 如果 `pctUsed <= 0` 或 `pctPerHour` 过低，显示“当前速度不足以预测耗尽”。

风险状态:

- `critical`: `pctUsed >= 90`，或 `willExhaustBeforeReset` 且 `etaHours <= 1`。
- `watch`: `pctUsed >= 75`，或 `willExhaustBeforeReset`。
- `ok`: 预计 reset 先发生，或 `pctUsed < 75` 且无耗尽预测。
- `unknown`: 限额数据缺失、过期或无法推算。

文案要求:

- 必须写清楚这是“限额百分比预测”，不是剩余 token 绝对值。
- 不显示“还能用 X token”。
- 对 `unknown` 不报错，不显示 0，也不强行给结论。

### 6.2 Real Cost View

目标: 让用户分清“等价成本”和“总 token 体积”，避免 cache read 让总 token 看起来虚高。

展示建议:

- 首屏 hero 保留 Token / 美元切换，但在 hero 下方增强 breakdown。
- 新增或强化三个数字:
  - Equivalent USD: 当前筛选区间等价 USD，继续标注非真实账单。
  - Fresh Tokens: `input + output + cacheWrite`。
  - Cache Read Share: `cacheRead / totalTok`。
- `totalTok` 降为辅助指标，不作为唯一大数字解释成本。

计算口径:

- 当前筛选区间、工具、项目、模型显隐均应生效。
- 从 `tokBreakdown` 汇总:
  - `freshTok = input + output + cacheWrite`
  - `cacheReadTok = cacheRead`
  - `totalTok = freshTok + cacheReadTok`
  - `cacheReadShare = totalTok > 0 ? cacheReadTok / totalTok : null`
- 从 `usdBreakdown` 汇总:
  - `usdTotal = input + output + cacheWrite + cacheRead`
  - 保留 input / output / cacheWrite / cacheRead 四类成本展示。
- Codex / OpenAI 本地日志当前未提供 `cacheWrite` 单独字段；界面应显示“没读取到”，JSON 里保留 `cacheWrite: 0` 只是兼容四分类结构，不应作为错误提示。

文案要求:

- `usd` 必须继续叫“等价 USD”或“API 价折合”，不能叫真实账单。
- cache read 占比高时的解释应中性，例如“cache read 占比高，总 token 会显得更大，但成本通常低于 fresh tokens”。

### 6.3 Today's Top Projects

目标: 用户能快速看到今天哪个项目最消耗额度和等价成本。

展示建议:

- 完整窗口保留现有“项目分布”，但 v0.2 必须增加“今日 Top 项目”视角。
- 位置建议在 Decision Strip 第三个单元，展示今日第 1 名项目；项目分布区可展示 Top 5。
- 点击 Top 项目后复用现有 `projectSelect` 过滤逻辑。

计算口径:

- “今日”使用 `daily[daily.length - 1].date`，即引擎已按 UTC+8 补齐后的最后一天，不使用浏览器本地自然日自行重算。
- 从 `daily[last].byProject` 汇总项目:
  - `tok`
  - `usd`
  - `freshTok`
  - `cacheReadShare`
  - `tools`
- 默认排序推荐按 `usd desc`，相同 USD 时按 `tok desc`。
- 展示 Top 5；如果空间不足，Decision Strip 只展示第 1 名，项目分布区展示 Top 5。

隐私要求:

- 默认展示 `project.name`。
- 不要求展示 raw absolute path。
- 如果展示 path，只能使用当前 engine 已脱敏/安全处理后的 `project.path`；不得重新引入 HOME 绝对路径泄露。
- `unknown` 项目应显示为“未知项目”，不能隐藏，否则总账会对不上。

## 7. 页面级验收标准

### 弹窗

- 能显示当前最紧的 5h / 7d 限额百分比。
- 若存在可预测的最紧窗口，显示 ETA 或“预计 reset 先发生”。
- 限额缺失时继续显示“未接入”，不出现 `NaN`、`undefined`、空白卡死。

### 完整窗口首屏

- 首屏能同时看到:
  - Burn-down Forecast 结论。
  - Equivalent USD / Fresh Tokens / Cache Read Share。
  - 今日 Top 项目第 1 名。
- 现有工具分页、项目筛选、Token / 美元切换仍可用。
- 切换工具、项目、周期、模型显隐后，Real Cost breakdown 和项目榜单同步刷新。

### 项目分布区

- 用户能看到今日 Top 5 项目，至少包含项目名、等价 USD、token 或 fresh token、工具标签。
- 点击项目后进入该项目筛选，hero、图表、breakdown、价格表与现有逻辑保持一致。

## 8. 数据和隐私验收标准

- 不读取、不解析、不展示对话正文。
- 不新增任何需要上传数据或访问外网的流程。
- 所有按天统计继续使用 UTC+8。
- 不改变现有 cache write 5m / 1h、cache read、去重、`<synthetic>` 过滤口径。
- 不把 raw HOME 路径写入公开响应、页面或新 JSON 字段。
- `usage.json` 缺少某个工具、某个 limit、某个 project 时页面必须降级显示，不崩溃。
- 所有新增文案继续保留“等价价值，非真实账单”的含义。

## 9. Dev Agent 实现边界

推荐最小实现:

1. 在 `web/index.html` 中增加纯前端推导函数:
   - forecast from `limits + updatedAt`
   - real cost from `tokBreakdown/usdBreakdown`
   - today top projects from `daily[-1].byProject`
2. 保持现有 `engine/usage-data.mjs` 核心合并逻辑不变。
3. 只有在能保持低风险时，才增加可选 JSON 摘要字段；不得为 v0.2 重写 source adapters。
4. 不引入新依赖。
5. 不新增读取正文的代码路径。

不建议 Dev 在 v0.2 做:

- 为了最近 1h / 3h velocity 大改 entry 粒度。
- 新增 session/window 数据模型。
- 新增复杂 chart library。
- 新增设置页或汇率服务。

## 10. v0.3 延后项

延后到 v0.3:

- session/window 下钻: 项目 -> session 列表，展示起止时间、token、新生成、调用数。
- 当前窗口上下文监控: 读取每个 session 最新 assistant usage，估算上下文占用。
- 最近 1h / 3h 真实 token 速度: 需要保留或输出小时级 timestamp 聚合。
- 绝对 quota / remaining tokens: 只有数据源明确提供 quota 后再做。
- RMB 估算: 需要本地可配置汇率或明确固定汇率标注。
- 错误/重试浪费统计。
- 模型降级省钱假设计算器。
- 任务级成本和手动标签。

## 11. 风险和开放问题

- 目前限额只有百分比和 reset 时间，没有绝对 token quota。因此 Burn-down Forecast 是百分比窗口预测，不是绝对 token 预测。
- ClaudeMeter 或 Codex 限额快照可能 stale。UI 应显示 as-of 时间，并在明显过期时降低置信度。
- 当前统一 `entries` 已按天聚合，v0.2 不应强行承诺真实最近 1h / 3h token 速度。
- 项目路径展示需要继续遵守防路径泄露规则。
- 如果同时存在 Claude Code 和 Codex，菜单栏和弹窗默认应继续用“最紧额度”策略；完整窗口则允许按工具分页查看。

## 12. Definition of Done

Dev Agent 完成 v0.2 时，Product 验收按以下清单判断:

- [ ] 弹窗能给出最紧限额的 ETA 或 reset-first 结论。
- [ ] 完整窗口首屏能回答“还能不能继续跑、真实等价成本是多少、今天哪个项目最烧”。
- [ ] Real Cost View 明确区分 fresh tokens、cache read tokens、equivalent USD。
- [ ] 今日 Top 项目使用 UTC+8 今日数据，默认按 USD 排序。
- [ ] 所有新功能在 Claude-only、Codex-only、双工具、有/无限额数据情况下都能降级显示。
- [ ] 没有读取或展示对话正文。
- [ ] 没有重写 engine 核心计费和去重口径。
- [ ] `node --check engine/lib.mjs engine/sources/claude.mjs engine/sources/codex.mjs engine/usage-data.mjs` 通过。
- [ ] `node engine/usage-data.mjs` 通过，且 JSON 不泄露 raw HOME 路径。
- [ ] `./app/build.sh` 通过。

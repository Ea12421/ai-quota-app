# v0.5 Product Brief: Quota Velocity Forecast

状态: Ready for Implementation

负责人: 产品经理

日期: 2026-06-27

## 1. 背景

v0.2 已有 Burn-down Forecast，但第一版主要用 `pct + resetAt` 推导窗口平均速度。用户后续确认需要更接近实时的判断: 不只问“这个窗口平均会不会耗尽”，还要问“最近 15 / 60 分钟突然加速时，是否应该暂停 Agent”。

本轮仍坚持本地只读、不读取正文、不上传数据、不做绝对剩余 token 编造。

## 2. 一句话目标

让人和 Atmo Agent 在开工前能看到 5h / 7d 额度的短窗口速度、最保守 ETA、数据是否陈旧，并据此决定继续、降速、checkpoint 或暂停。

## 3. 必做范围

### P0.1 限额百分比短窗口速度

目标: 用真实 rate limit 百分比快照计算更实时的消耗速度。

必须支持:

- 最近 15 分钟百分比速度。
- 最近 60 分钟百分比速度。
- 窗口平均速度。
- 取最保守的速度口径作为 ETA basis。
- 如果 15m / 60m 样本不足，明确回退到窗口平均，不伪造实时速度。

验收:

- `usage.json` 输出最近限额快照，且不包含 secret、token、cookie、authorization。
- quota API 响应中能看到 forecast basis，例如 `15m`、`60m`、`window_avg` 或 `insufficient`。
- 当短窗口速度比窗口平均更危险时，ETA 使用短窗口速度。

### P0.2 token 使用速度辅助视图

目标: 用 token/hour 辅助解释最近是否在爆量，但不把 token 直接换算成剩余额度。

必须支持:

- `usage.json` 输出 `usageVelocity.windows.15m` 和 `usageVelocity.windows.60m`。
- 每个窗口包含 `tokPerHour`、`usdPerHour`、`modelCallCount`、`byTool`。
- 看板 Burn-down / 限额卡能展示最近 15m token/hour 作为辅助上下文。

验收:

- 无近期调用时显示 0 或不展示速度，不出现 `NaN` / `undefined`。
- token velocity 不作为绝对 quota 计算依据，文案不能说“还能用 X token”。

### P0.3 quota API velocity gate

目标: Atmo Coordinator 查询 `/quota` 时能基于实时速度做更保守的开工判断。

必须新增或保留字段:

- `windows.*.forecast.basis`
- `windows.*.forecast.basis_cn`
- `windows.*.forecast.pct_per_hour`
- `windows.*.forecast.eta_minutes`
- `windows.*.forecast.eta_text`
- `windows.*.forecast.will_exhaust_before_reset`
- `windows.*.forecast.risk_reason`
- `windows.*.token_velocity.15m`
- `windows.*.token_velocity.60m`
- `windows.*.data_freshness`

策略要求:

- `5h` 如果按当前速度会在 reset 前很快耗尽，应进入 `danger`，并 `should_pause_running_agents = true`。
- `7d` 如果按当前速度会在 reset 前耗尽，应至少进入 `tight`，短期内耗尽则进入 `danger`。
- 任一窗口数据明显陈旧时，不误报完全正常；至少不允许 heavy task。
- API 失败或数据源不可用时仍返回合法 JSON，状态为 `unknown`。

验收:

- `curl /quota` 返回合法 JSON。
- `normal / tight / danger / exhausted / unknown` 仍可模拟。
- danger / exhausted 下暂停策略明确。
- normal 恢复后 `should_resume_paused_agents = true` 的旧逻辑不被破坏。
- 响应不包含敏感字段。

### P0.4 Dashboard 展示预测口径

目标: 用户能看懂当前预测为什么这么判断。

必须展示:

- Burn-down Forecast 使用的口径: 最近15分钟 / 最近60分钟 / 窗口平均 / 数据不足。
- 百分比速度，例如 `3.2%/h`。
- 最近 15m token/hour 辅助速度。
- 数据陈旧时给出“快照偏旧”提示。

验收:

- 完整窗口和菜单栏弹窗不出现布局明显溢出。
- 旧数据结构缺少 `limitSnapshots` 或 `usageVelocity` 时仍能正常显示。
- 不新增复杂页面，不影响 v0.4 的 Project Monitor / 任务标签 / Agent 趋势。

## 4. 非目标

本轮不做:

- 绝对剩余 token quota。
- 读取或展示对话正文。
- 语义分析、自动任务分类。
- 机器学习预测。
- 未来任务消耗自动估算。
- 人民币估算。
- 完整 session/window 下钻。
- 模型降级省钱计算器。

## 5. 数据与隐私口径

允许读取和输出:

- timestamp。
- tool。
- model。
- project id / project name。
- usage token / USD breakdown。
- rate limit used percent / resetAt。

禁止读取或输出:

- `message.content`。
- prompt / response 正文。
- secret、token、cookie、authorization。
- 原始本机绝对路径。

新增派生字段不得改变:

- `daily[]`
- `projects[]`
- `sessions[]`
- `limits`
- UTC+8 按天口径。
- Codex 累计快照去重。
- Claude cache write / cache read 计费口径。

## 6. 推荐实现顺序

1. 数据源输出只读 `usageEvents` 和 `limitSnapshots`。
2. `engine/usage-data.mjs` 聚合成 `usageVelocity`，并保留最近限额快照。
3. `engine/quota-api.mjs` 用 15m / 60m / window average 合成 forecast。
4. `web/index.html` 展示 basis、pct/hour、15m token/hour、stale 提示。
5. README 和产品文档同步。
6. 跑语法检查、数据生成、mock quota、构建。

## 7. Review 重点

质量评审应重点看:

- 没有读取或展示对话正文。
- 没有把 token/hour 硬换算成绝对剩余额度。
- `daily/projects/sessions/limits` 向后兼容。
- quota API 失败降级仍是 JSON unknown。
- stale 数据不会误报可安全 heavy task。
- mock 覆盖 15m / 60m / window_avg / unknown。
